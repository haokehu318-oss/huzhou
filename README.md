# 即案 FLASHPLAN · 户外投放 AI 提案工作台

INTERCITY HACK 湖州场 · 新云传媒命题。给定行业和预算，几十秒内产出一份可直接对客户演示的户外投放方案（公交车身 + 地铁出入口），所有线路、点位、可售数量都来自两套比赛系统的真实数据。

## 解决的痛点

销售出一份提案要好几天，时间花在四件事上：查哪些线路在门店附近、去红豆核对档期空位、翻刊例算价、排上刊计划。工作台把这四步串成一条自动链路：

```
品牌门店（大数据平台 POI 检索）
  → 覆盖匹配（线路轨迹 500 米内途经 / 地铁口直线距离 800 米内）
  → 可售过滤（红豆库存，整段档期都空才算可售，已扣合同、预定、保养、续约保护）
  → 预算内择优（人次 × 门店相关度，覆盖新门店加分，同线加车频次递减）
  → 报价（资料包刊例口径）+ 上刊倒排（施工产能、雨天缓冲、广告审查期）
  → 单文件 HTML 提案
```

预算在 100–500 万之间拖动时实时重算（< 60 ms），并列出相对上一版或基准方案增减了哪些线路，评委现场改预算可以当场讲清楚"多出来的钱买了什么"。

## 运行

需要 Node.js 18+，无第三方依赖。

```powershell
node server.mjs            # 打开 http://127.0.0.1:5188/
npm test                   # 5 个行业 × 3 档预算的约束测试
node tools/make_reports.mjs  # 批量导出 15 份提案到 outputs/（路演备份）
```

不连比赛系统也能完整演示：`web/data/` 里有 2027 全年 12 个月的红豆库存快照、大数据平台的线路轨迹/人次/坐标和 5 个品牌的门店。连上系统后多两个能力：

| 能力 | 需要 | 如何连接 |
|---|---|---|
| 红豆实时核对可售 | 红豆令牌 | 浏览器登录红豆后点右上角「红豆库存」，粘贴 Local Storage 里的 ACCESS_TOKEN / REFRESH_TOKEN；或在本机运行 `node tools/edge_token.mjs` 从 Edge 读取（只读该站点这两个键）。服务端用 refresh token 自动续期 |
| 检索任意品牌门店、提案内平台覆盖复核 | 大数据平台会话 | 点右上角「大数据平台」，输入账号密码和图片验证码 |

账号密码不写进代码：可在弹窗输入，或设环境变量 `BD_USER` / `BD_PASS`。令牌和 cookie 存在 `data/`（已 gitignore）。

可选：设 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`（任一 OpenAI 兼容接口）后，brief 解析会在规则解析之外用大模型补字段。不设也能用。

## 对照《好提案的标准与需求定义》

- **campaign 假设书**：左侧「campaign 假设书」七要素可编辑，⑤⑥ 随预算、档期、媒体自动生成；导出提案第二章「假设书与方案回应」逐条对应方案做法。
- **5 个参考 brief**：「粘贴客户 brief」里可直接选文档第六节的参考 brief，一键解析为行业、预算、档期、媒体和目标。
- **提交前 10 条自检**：工作台底部实时打勾（绿 / 黄 / 红），例如未做红豆实时核对时第 6 条为黄。
- **提案正文**：选点证据链（门店 → 半径内媒体 → 有空位 → 入选）、组合主次与取舍理由、各媒体预算占比、效果预估口径（日均人次 × 天数，未去重）、监测交付、风险与备选替换线路。
- **数据合规**：红豆占用明细里的其他客户品牌只显示首字，提案中不出现；价格均为资料包刊例口径。

## 演示脚本（3 分钟）

1. 默认是「银行保险 · 招商银行 · 200 万 · 3 月」。指出地图上的红线是选中的公交线路、方框是地铁口、黑点是被覆盖的网点。
2. 点「红豆实时核对可售」，按当前档期实时查询红豆，方案按实时空位自动调整，页脚显示查询时间。
3. 点「500 万」，右侧「变化」列出新增的线路；再点「100 万」，看减掉了什么。
4. 评委指定行业：点对应行业按钮。保健品和私立医院会自动预留 20 个工作日广告审查期，倒排里能看到客户最晚定稿日提前。
5. 评委指定别的品牌：在「目标品牌」输入品牌名点「检索门店」，实时去大数据平台拉门店。
6. 点档期下方的月份柱可多选（如 3、4、9 月），不连续的月份分段上画、制作费按段计。
7. 客户点名线路：第 5 步输入「18路」或「人民广场 1号口」，详情卡直接显示本档期可售/合同/预定/保养、12 个月可售、人次和价格；可加减数量，剩余预算由系统补足（可关掉只看指定线路）。
8. 客户只给地址：选「按客户具体地址」，每行一个地址，查询后列出服务半径内全部公交线路和地铁口（按距离排序，可一键指定），并按预算自动组案。
9. 「生成客户提案」：打开并下载单文件 HTML，离线可开，表格行悬停会在地图上高亮对应线路。

```powershell

node tools/bd_labels.mjs detail  # 坐标、轨迹、站点人流（断点续传）

node tools/bd_extra.mjs          # 名称不一致线路补抓

node tools/bd_fullpaths.mjs      # 地图用全精度公交轨迹 → web/data/paths-full.json
node tools/snap_roads.mjs        # 轨迹吸附到道路（OSRM，1 次/秒，全量约 3 小时，可断点续传）→ paths-road.json
```

## 红豆可售口径（已核实）

- 红豆按日期区间查询时，空车数等于区间内每一天空车数的最小值，即"整段档期都空才算可售"。用 1015 路核对：2 月逐日 2 辆、3 月 30–31 日保养 1 辆，按月查 3 月返回 1、按 2–3 月区间查返回 1。
- 空车 = 总量 − 合同 − 预定 − 保养 − 续约保护。167 路 4–5 月：11 − 2 − 6 − 0 = 3，与区间、逐月、逐日三种查法一致，合同/预定明细与红豆「占用明细」接口一致。
- 工作台离线快照按自然月存，多月档期取各月最小值，与区间查询等价；详情卡「向红豆核对」会按当前档期逐段实时查询并列出占用订单。

## 关键口径与假设

- 公交刊例取资料包《05 饮用水提案样本》成交价：S 58,000 / A++ 48,000 / A+ 38,000 元·辆·月，制作 5,000 元/辆，均在《07 刊例价》区间内。地铁口 A++ 30 万、A+ 20 万（07 区间中值），制作 100 元/㎡，面积缺失时按 30㎡。S 级地铁口和 AA 观光线 07 未直接列价，标"待核价"。
- 折扣默认按刊例，可在「报价与施工参数」调整。真实折扣口径以培训说明为准。
- 人次是平台「媒体查询」2023 年 5 月的历史日均人流（公交为线路沿线、按线路计一次，与车辆数无关；地铁口为出入口周边），各媒体相加未去重，只用于排序和量级展示，不是广告实际被看到的人次。
- 单晚施工 20 台车 / 6 个地铁口、每 4 夜留 1 夜雨天缓冲是假设值，可在界面调整。
- 红豆公交库存 430 条线路（按资源 ID 去重），427 条关联到线路轨迹，346 条有平台人次（其余按同类中位数六折估，标"估"）；861 个地铁口中 813 个有坐标（102 个出口借用同站其他出口坐标，标"同站参考"）。
